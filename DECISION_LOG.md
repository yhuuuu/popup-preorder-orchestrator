# Decision Log

| Date       | Decision                                                       | Reason                                                                 | Trade-off                                |
| ---------- | -------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------- |
| 2026-08-03 | Use pop-up pre-order theme instead of inventory-heavy commerce | Matches real vendor workflow and user insight; better interview story  | Less focus on inventory APIs             |
| 2026-08-03 | Use TypeScript + Express                                       | Aligns with existing React/TS background and tech-company expectations | Slightly more setup than plain JS        |
| 2026-08-03 | Prioritize API + webhook before frontend                       | Fastest path to implementation-role proof points                       | UI demo delayed                          |
| 2026-08-03 | Keep MVP webhook retry to max 3 attempts                       | Simple, realistic reliability behavior                                 | Not full production-grade retry strategy |
| 2026-08-28 | Keep CORS restricted to configured frontend origins            | Protects the API from arbitrary browser origins while supporting local development | Local frontend ports must be listed in `FRONTEND_ORIGIN` |
| 2026-08-28 | Support comma-separated CORS origins                            | Allows Vite to use either local development port 5173 or 5175         | Requires parsing and validating the configuration as an allowlist |
| 2026-08-28 | Load `app/.env` with node's `--env-file-if-exists` instead of adding `dotenv` | The API previously never read `.env`, so `FRONTEND_ORIGIN` was ignored and silently fell back to the hardcoded `http://localhost:5173`; uses the built-in runtime flag rather than a new dependency | Env loading now lives in the npm scripts, so any new way of starting the server must pass the same flag |
| 2026-08-28 | Stop tracking `web/.env` in git                                 | It held `VITE_API_TOKEN` and was committed, unlike the already-ignored `app/.env` | The old value stays in git history, so the dev token should be rotated rather than assumed private |
| 2026-08-30 | Move one-item-per-order to `order_items` + `menu_items` (many-to-one) | Real pop-up customers order several flavours per order, each with its own quantity | Required migrating existing orders and rewriting validators/routes/tests/frontend |
| 2026-08-30 | Restrict pickup time to a fixed slot list (`GET /api/pickup-slots`) instead of a free-text field | The pop-up only offers 1:00 PM / 3:00 PM pickup; a free-text field allowed invalid times | Any new slot requires a code change, not just a config value |
| 2026-08-31 | Replace the hand-built frontend with a Lovable-generated TanStack Start dashboard, keeping the UI components verbatim and rewriting only the data layer (`src/lib/orders/`) | Lovable's own scaffolding already isolated all HTTP calls behind one file, making a full swap low-risk; the generated UI/UX was more polished than the original | The generated project invented its own data model (single item, camelCase) that had to be fully reconciled against the real API; original custom frontend was discarded (kept only as a local backup, not in git) |
| 2026-08-31 | Add `search`/`status` filters to `GET /api/orders` at the SQL level, not client-side | Client-side filtering would desync `total`/pagination from the actually filtered result set | Requires a correlated `EXISTS` subquery against `order_items`/`menu_items` for flavour search |
| 2026-08-31 | Use `npm install` instead of `npm ci` for the frontend job in CI | `rolldown`'s optional platform-specific dependencies resolve differently between macOS (where the lockfile is generated) and the Linux CI runner, making `npm ci` fail with a spurious lockfile-mismatch error | CI no longer guarantees an exact reproducible install for the frontend job (backend job still uses `npm ci`) |
